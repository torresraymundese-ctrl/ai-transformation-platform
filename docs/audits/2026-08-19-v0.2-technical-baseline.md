# V0.2 Technical Baseline — 2026-08-19

## Scope

This baseline records the production-code snapshot, current runtime state, automated behavior, and code-level quality risks before the 2.0 upgrade. It is not a visual UX audit: browser screenshot capture was unavailable in the current runtime, so visual, responsive-reflow, keyboard, focus-order, and assistive-technology checks remain pending.

- Gunicorn bind: `0.0.0.0:5080`.

- Asset dashboard.
- Asset code management.
- Department management.

- Asset-label printing.
- Supporting asset tables and seed data.

## Automated behavior baseline

Command:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Current result:

- 23 passing behavior tests.
- 6 strict expected failures documenting known security gaps.
- Disposable SQLite database per test; no production data is used.

Covered behavior:

- Nine public routes and static assets.
- Health-check JSON contract.
- Unauthenticated admin rejection.
- Eleven authenticated admin routes.
- Assessment submission and database persistence.

Known security gaps captured as strict expected failures:

1. Empty assessment objects are accepted.
2. Non-object JSON is not handled safely.
3. Invalid email addresses are accepted.
4. Overlong company names are accepted.
5. Stored article scripts are rendered without sanitization.
6. Authenticated admin writes do not require CSRF tokens.

## Code-level UX, accessibility, and SEO observations

These observations are based on templates and HTTP output only, not screenshots:

- Pages provide a Chinese language declaration and viewport metadata.
- Public pages use H1 headings and include responsive media queries.
- No page-level meta description, canonical URL, Open Graph, or Twitter metadata was found.
- The home hero forces a no-wrap heading, creating a likely narrow-screen overflow risk.
- The mobile rule hides the primary navigation links without an evident replacement menu.
- Assessment contact inputs use placeholders without persistent labels.
- The logo alternative text is generic rather than identifying the organization.
- No reduced-motion preference handling was found despite scroll and glow animations.
- No skip link or consistent global keyboard-focus treatment was found.
- Many interactions rely on inline `onclick`, inline focus handlers, and inline styling.
- The case-page heading says 24 cases while the underlying seeded catalog and other copy refer to 27.

## Phase 2 priority

1. Remove hard-coded credentials and rotate the exposed production credential.
2. Introduce configured authentication, sessions, CSRF, validation, sanitization, rate limiting, and audit logging.
3. Split routes and responsibilities without changing public behavior.
4. Extract shared CSS and JavaScript while retaining the V0.2 appearance until the 2.0 design phase.
5. Add database migrations and preserve backward compatibility.
6. Convert the six strict expected failures into passing security tests.
