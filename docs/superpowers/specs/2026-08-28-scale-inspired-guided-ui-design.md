# 企业 AI 转型平台 2.0：Scale 启发式五章滚动叙事设计规格

- 日期：2026-08-28
- 状态：设计方向已获用户口头确认，等待本书面规格确认
- 适用范围：公共首页、AI 场景目录、场景详情，以及后续公共页面对同一视觉系统的接入
- 上游规格：`docs/superpowers/specs/2026-08-26-enterprise-ai-platform-ui-design.md`
- 视觉参考：Scale AI 当前官网首页 `https://scale.com/`，以及用户于 2026-08-28 明确选定的“任务驱动、冷峻、工业级、真实产品界面进入首屏”方向
- 数据决定：没有可公开的真实客户背书时，只使用现有已发布数据或明确标注的演示数据
- 生产边界：仅限本地设计、开发和演示；全部功能开发、独立审查与完整测试通过前不得部署或改动生产环境

## 1. 规格关系与目标

本规格不替换 2026-08-26 全站 UI 规格中的业务、安全、数据、响应式和可访问性边界，只替换其公共端视觉方向、首页信息架构、动效规则和资产策略。后台仍以运营工作台为主，不套用营销首页的沉浸式滚动。

目标不是复制 Scale AI 的品牌、文案或素材，而是借鉴其设计方法：用一句强主张建立任务感，用真实产品表面证明能力，用黑、暖白、冷灰和少量信号色形成秩序，再通过滚动逐步解释复杂系统。

本轮必须解决：

1. 首页不能继续是纯色 Hero 加文字卡片的普通企业官网结构。
2. 用户在首屏后每次向下浏览，都应看到一个明确的新问题、新产品状态和下一步指导。
3. 科技感必须来自真实界面、数据关系、排版和状态变化，不来自虚构仪表盘、霓虹装饰或无意义循环动画。
4. 场景目录和场景详情必须延续同一设计系统，而不是首页改版后仍保留旧式文本平铺。

## 2. 已确认的设计方向

### 2.1 视觉性格

- **任务驱动**：标题陈述企业必须解决的业务问题，不使用泛化的“赋能、领先、智慧未来”等口号。
- **冷峻工业感**：使用严格网格、细分隔线、真实界面和高对比排版；减少圆角、阴影和装饰性卡片。
- **可信而非炫技**：每个视觉焦点都对应评估、场景匹配、实施路径、服务或证据中的真实能力。
- **编辑式节奏**：大标题、短段落、大面积留白与高密度产品画面交替出现，一屏只讲一个结论。

### 2.2 借鉴边界

- 可以借鉴 Scale AI 的公告栏、极简导航、全幅真实界面、超大主张、黑白章节切换和滚动叙事节奏。
- 不复制 Scale AI 的 Logo、商标、客户名称、排行榜、文案、摄影、图标、界面截图或动效实现。
- 使用平台现有 Logo、路由、已发布内容和本地确定性演示数据。
- 不将“参考风格”解释为逐像素克隆；成品必须能清楚识别为企业 AI 转型平台。

## 3. 首页五章滚动叙事

首页采用一个自然文档流中的五章故事。桌面端在故事区域使用粘性产品舞台和章节状态切换；用户可快速滚过，不被脚本锁住。手机端改为自然纵向展开。

### 第 1 章：为什么需要转型

- 目的：建立平台使命和核心业务判断。
- 推荐主张：“关键的业务场景，需要可验证的 AI 落地路径。”最终文案在实现前进行一次中文编辑校对。
- 视觉：平台真实评估或决策界面作为全幅背景，经黑色遮罩控制可读性；不是纯深蓝色块。
- 动作：主要行动“开始 AI 就绪度评估”，次行动“浏览 AI 场景”。
- 第一次滚动后，遮罩和标题退到次级层级，真实界面进入可读状态。

### 第 2 章：先评估当前准备度

- 目的：说明平台先诊断再推荐，不直接销售方案。
- 文本说明评估维度和输出，不展示虚构行业平均值。
- 产品状态：从未评估状态切换为确定性演示结果，显示评分、短板和说明。
- 所有非真实用户结果必须紧邻显示“演示数据”，不能仅在页脚免责声明中说明。

### 第 3 章：匹配高价值场景

- 目的：展示行业、部门、成熟度如何共同影响推荐。
- 产品状态：场景矩阵逐步高亮已验证的筛选条件和匹配项；标题、摘要、周期和预算来自公开 view model。
- 不显示虚构的“命中率、节省金额、企业使用数”。
- 行动指向现有场景目录和场景详情路由。

### 第 4 章：形成实施路径

- 目的：把场景从“可看”推进到“可执行”。
- 产品状态：依次呈现前提、输入、步骤、指标、风险、周期、预算和服务支持。
- 路径状态来自现有已发布场景和服务数据；没有字段时遵循现有 fail-closed 或“评估后确认”规则，不在前端补造。
- 使用顺序、连接和状态变化解释路径，不用抽象发光线条代替内容。

### 第 5 章：用证据进入下一步

- 目的：收束可信度并引导评估。
- 优先使用已审核案例、公开资源和平台能力说明。
- 没有真实客户授权时，不展示第三方 Logo、客户引语或假 ROI；确定性种子内容必须标记“演示案例”或“演示数据”。
- 最终行动为“开始评估”，辅助入口为“查看服务与交付”。

## 4. 滚动与动效行为

### 4.1 桌面行为

- 每章的阅读空间约为 `100svh` 至 `140svh`，产品舞台可在该故事区内 `position: sticky`，不得覆盖导航、页脚或系统提示。
- 使用 `IntersectionObserver` 或等价渐进增强机制，在章节进入约 45%—55% 观察区时切换产品状态。
- 允许 `scroll-snap-type: y proximity` 等柔性吸附；禁止 `mandatory` 全页锁定。
- 禁止监听 `wheel` 后调用 `preventDefault()` 模拟翻页；触控板、快速滚动、滚动条拖动和查找定位必须保持浏览器原生行为。
- 向上滚动时，产品舞台按章节状态自然回退。
- 页面显示 `01—05` 章节进度，可点击跳转到语义化锚点。
- 状态过渡建议为 500—800ms；只动画 `opacity` 和 `transform` 等合成友好属性，不持续循环。

### 4.2 键盘与可访问性

- 章节本身保持普通文档语义，标题顺序连续；进度导航为可聚焦链接。
- Page Down、Space、方向键和浏览器查找使用原生滚动，不依赖自定义键盘处理。
- 跳转后焦点和可见位置不能被 sticky 导航遮挡，使用受控 `scroll-margin-top`。
- `prefers-reduced-motion: reduce` 时关闭粘性状态过渡和吸附，五章内容按静态顺序完整呈现。
- JavaScript 不可用时，所有章节文本、真实截图和行动入口仍可阅读和操作。

### 4.3 移动端

- `< 768px` 不使用强制吸附或长时间粘性舞台。
- 每章按“标题—说明—对应产品画面—行动”自然纵向排列。
- 动效缩短为 160—240ms 的出现/状态变化；不能因为浏览器地址栏高度变化产生跳屏。
- 触控目标至少 44×44px，页面在 320px 宽度无横向溢出。

## 5. 视觉系统

### 5.1 色彩

| 语义 | 建议值 | 用途 |
|---|---|---|
| `graphite-1000` | `#07090D` | 首屏、关键沉浸章节 |
| `graphite-950` | `#0D1117` | 深色产品舞台和页脚 |
| `graphite-800` | `#252B33` | 深色分隔与次级信息 |
| `paper-050` | `#F3F1EB` | 暖白编辑式章节背景 |
| `surface-000` | `#FFFFFF` | 产品界面和主要阅读表面 |
| `ink-950` | `#11151B` | 浅色背景主文本 |
| `ink-600` | `#5B6470` | 次级说明 |
| `signal-blue` | `#0F6FEF` | 主要行动、活动状态、关键数据 |
| `signal-cyan` | `#5BD9E8` | 极少量系统状态和图表强调 |
| `line-dark` | `#343B44` | 深色表面分隔 |
| `line-light` | `#D8DDE3` | 浅色表面分隔 |

品牌蓝只作为信号色，不能再次形成整页蓝色背景。正文、按钮、焦点和状态达到 WCAG 2.2 AA；状态不只依赖颜色。

### 5.2 字体与层级

- 不从外网加载字体，继续使用系统中文无衬线字体栈。
- 桌面首屏标题建议使用 `clamp(3.5rem, 6.5vw, 6.75rem)`，行高 0.98—1.08，控制在两至三行。
- 章节标题建议 40—64px；正文 16—20px；关键数字使用等宽数字特性但不引入远程字体。
- 文字宽度必须经过编辑：主张不超过约 18 个汉字一行，长正文约 60—65 个汉字一行。

### 5.3 网格、形状和表面

- 桌面内容最大宽度提高到约 1360px；页面 gutter 为 24—40px，依视口流动。
- 使用 12 栏严格网格和 1px 分隔线；产品舞台允许跨 7—8 栏，叙事文本使用 4—5 栏。
- 常规表面圆角 0—6px；只有输入控件、按钮和必要浮层可使用 6—8px。
- 禁止把全部内容做成同尺寸白色圆角卡片；卡片只用于可比较、可操作或有独立边界的对象。
- 阴影只用于浮层和产品界面分层，常规章节依靠对比、留白和分隔线。

## 6. 真实产品画面与生成图片

### 6.1 真实产品画面优先

- 首屏和第 2—4 章优先使用本地确定性 fixture 中的真实平台界面，而不是 AI 生成的假界面。
- 截图必须脱敏，不含真实联系人、手机号、邮箱、访问令牌或生产数据。
- 截图在目标插槽尺寸确定后再捕获，避免放大低分辨率图片或错误裁切。
- 如果直接使用 HTML 产品舞台，应继续消费现有 view model，不能为动效新增数据库查询或绕过状态门禁。

### 6.2 允许生成的科技风格图片

可以生成最多两类装饰性位图：

1. 深色工业数据基础设施的抽象环境图，用于章节间的氛围过渡。
2. 黑、灰、品牌蓝体系的企业级计算/连接空间图，用于最终行动区。

生成图片必须满足：

- 不生成客户 Logo、虚构数据、假产品截图、假人物证言、奖项或安全认证。
- 不把生成图当作业务证据；装饰图使用空 `alt`，不进入可读内容语义。
- 在插槽尺寸、裁切比例、焦点位置和移动端策略确定后再生成；每张图独立验收。
- 记录生成来源和用途，压缩为本地 WebP/AVIF 或等价高效格式，不在运行时请求外网。
- 首屏优先加载真实产品画面；装饰图不得成为核心信息的唯一载体。

### 6.3 视频决定

- 本轮不使用视频、自动播放媒体或大体积背景循环。
- 滚动状态、静态产品界面和少量位图已经足以建立节奏；未来加入视频必须另行设计和性能审查。

## 7. 场景目录与详情的延续

### 7.1 场景目录

- 顶部从普通表单筛选改为“场景信号面板”：行业、部门、成熟度仍使用现有可提交字段，但视觉上采用严谨分组和即时结果摘要。
- 场景项展示真实分类、周期和预算，使用分隔式编辑网格而不是等宽白卡阵列。
- hover/focus 通过边框、文本和背景状态表达，不做上浮卡片动画。
- 筛选、分页、空状态和 URL query 行为保持不变。

### 7.2 场景详情

- 首屏变为“决策封面”：标题、摘要、分类和核心行动与真实产品式摘要共同呈现。
- 正文维持三章业务结构，但将章节导航、指标、风险和实施路径升级为同一工业网格语言。
- 右侧摘要不重复服务包；同一服务只出现一次，并保留 published-only 数据边界。
- 桌面可使用粘性章节目录或摘要，移动端回到正常文档流。

## 8. 数据与文案规则

- 首页产品演示使用确定性 fixture 时，相关区域必须显示“演示数据”；标识颜色和字号达到可读要求。
- 行业、场景、服务、案例和资源仍以已发布 view model 为唯一事实来源。
- 没有可公开真实客户资料时，不出现客户墙、客户 Logo、引语、节省百分比、ROI 或使用规模。
- 不能为了模仿参考网站而更改评估结论、场景匹配、预算、周期或服务关系。
- 主标题和章节引导可以进行品牌编辑，但不得暗示未经证明的结果。

## 9. 技术与性能边界

- 继续使用现有 Flask/Jinja/CSS/JavaScript，不引入 SPA、CSS 框架或新模板引擎。
- 不新增生产 API、数据库 schema 或业务状态机。
- 不加载第三方字体、远程图标、远程脚本或运行时外部图片。
- 动效使用渐进增强；服务端 HTML 是完整内容，JavaScript 只同步状态和交互。
- 不使用自定义滚轮接管、持续视差、WebGL 背景、粒子系统或大面积模糊滤镜。
- 首屏新增关键图片单张建议不超过 350KB，首屏新增总图片预算建议不超过 800KB；图片提供明确尺寸，避免布局偏移。
- 本地开发、截图和测试只绑定 `127.0.0.1`，不访问生产服务器、Nginx、systemd、真实数据库或真实业务端点。

## 10. 实施范围与顺序

1. **首页滚动骨架**：五章语义结构、真实内容、无 JavaScript 降级和行为测试。
2. **首页视觉与产品舞台**：Scale 启发式导航、色彩、网格、真实产品画面和桌面/移动布局。
3. **滚动状态与无障碍**：IntersectionObserver、进度导航、减少动效、键盘和快速滚动行为。
4. **场景目录与场景详情**：将已确认的视觉系统延续到两个核心决策页面。
5. **生成图片与性能**：只在插槽测量后生成必要的最多两类装饰图，压缩并验证。
6. **视觉 QA 与独立审查**：同视口对照 Scale 参考、批准规格和本地实现；修复 P0—P2 后停在审查门禁。

后续行业、服务、案例、资源、评估/报告和后台页面在核心三页确认后逐批接入，不在本轮偷偷扩大修改范围。

## 11. 测试与验收

### 11.1 TDD 与自动化

- 所有模板结构、状态切换、导航和降级行为先建立真实 RED，再实施 GREEN。
- HTTP 测试至少断言五章语义、两项真实行动、演示数据标识、无视频、真实内部路由和无 JavaScript 时完整内容。
- JavaScript 事件级测试至少覆盖章节进入、向上回退、进度跳转、重复 observer 事件、减少动效和缺少 API 时的安全降级。
- 静态/运行时测试证明没有通过 `wheel` + `preventDefault()` 接管滚动。
- 保留已有公开内容、安全、canonical、published-only、URL 和 HTML 清洗回归。

### 11.2 浏览器设计 QA

- 参考捕获和实现截图使用相同桌面视口；将 Scale 参考图与本地成品放入同一比较输入后再判断差异。
- 首页至少捕获五章的稳定状态，以及 390×844 的完整移动流。
- 验证鼠标滚轮、触控板式快速滚动、滚动条拖动、反向滚动、锚点跳转、刷新恢复和页脚到达。
- 验证 Tab、Shift+Tab、Enter、Space、方向键、Page Down、Escape，以及 200% 文本缩放。
- 验证 `prefers-reduced-motion` 后不再吸附或动画，但信息不丢失。
- 检查控制台错误、布局偏移、横向溢出、图片裁切、首屏加载和 sticky 越界。

### 11.3 完成门槛

本轮只有同时满足以下条件才可标记完成：

1. 五章滚动叙事、场景目录和场景详情均使用同一视觉语言。
2. 真实产品画面来自本地脱敏 fixture；所有模拟结果都有就近“演示数据”标识。
3. 无滚轮劫持，移动端、减少动效和无 JavaScript 降级可用。
4. 自动化责任集、Node 测试、浏览器交互和同视口视觉对照均有新鲜证据。
5. 独立审查无未闭合 P0—P2；代码和证据按任务单独提交。
6. 未运行或声称未经计划允许的完整测试；最终完整测试仍由后续总验收门禁拥有。
7. 未部署、未开放公网、未触碰生产服务器或真实数据。

## 12. 非目标

- 不逐像素克隆 Scale AI，不复制其资产、品牌、文案或客户证据。
- 不使用视频、自动播放背景或音频。
- 不做强制整页滚轮锁定或阻止浏览器原生滚动。
- 不生成假产品界面、假客户、假数据、假指标或假认证。
- 不在本轮重做评估规则、内容发布、数据库、后台运营或部署流程。
- 不因首页动效破坏 SEO、服务端内容、键盘可达性或打印能力。

## 13. 决策摘要

- 主参考：Scale AI 的任务感、真实产品表面、黑白章节和工业秩序。
- 核心体验：五章自然滚动叙事，而非视频或滚轮劫持。
- 事实来源：已发布数据优先；没有真实客户材料时使用明确标注的演示数据。
- 图片策略：真实产品截图优先，最多生成两类非事实性科技氛围图。
