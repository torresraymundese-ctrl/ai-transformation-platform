# 企业 AI 转型平台 2.0：银灰证据系统公共页面视觉规格

- 日期：2026-08-31
- 状态：用户已通过书面规格（2026-08-31）
- 上游功能规格：`docs/superpowers/specs/2026-08-24-content-operations-design.md`
- 上游首页规格：`docs/superpowers/specs/2026-08-28-dark-evidence-homepage-design.md`
- 首页视觉基准：`docs/design/references/2026-08-31-silver-evidence-homepage-reference.png`
- 详情页视觉基准：`docs/design/references/2026-08-31-silver-evidence-detail-reference.png`
- 范围：全部公开页面；后台页面不在本轮范围
- 发布边界：只允许本地开发、测试和演示；不得部署、开放公网或改动服务器、Nginx、systemd、生产数据库

## 1. 设计目标

本轮不在旧白底卡片主题上继续换颜色，而是以平台现有功能为信息架构，重建一套统一的“银灰证据系统”。它应同时表达三件事：企业级可信、工业科技感和可验证的实施路径。

首页继续使用已经实现并审查通过的五章原生滚动叙事；视觉上恢复已选方案中的明亮银灰机械手、清晰高光和克制蓝色。其余公开页面采用与详情视觉基准一致的构图：暗色沉浸式封面、明亮工业图像、暖白编辑式正文、编号章节、横向事实带和深色实施/治理章节。

本规格改变公共页面的视觉表达和模板组合，不改变已发布内容模型、路由、筛选参数、评估流程、发布状态机、媒体安全、权限或数据库。

## 2. 绑定视觉证据

### 2.1 首页基准

`2026-08-31-silver-evidence-homepage-reference.png` 是首页色彩、机械手亮度、标题比例、留白和大区块节奏的绑定基准，SHA-256 为 `5DA39E614D5768BFE28D5C52FB5641C68C0BA1BF146B252BE10CCEA0C2C726CA`。

必须继承：

- 近黑背景与清晰的银灰机械结构，不能把机械手压成黑色剪影；
- 暖白大标题、灰白正文和单一电光蓝行动色；
- 一个首屏主按钮，后续入口按叙事章节出现；
- 少卡片、多整屏章节、横向细线和大图裁切；
- 五章原生滚动，不拦截滚轮或键盘默认滚动。

### 2.2 详情页基准

`2026-08-31-silver-evidence-detail-reference.png` 是行业、场景和服务详情页的页面骨架基准，SHA-256 为 `2287D6F8C5FCC8905FD3F19D0EF495607DDFAFC7E8D3428A1FBF5D062A80B588`。

必须继承：

- 桌面首屏为左侧暗色标题与右侧明亮产业图像的分栏构图；
- 标题下方使用一条横向事实带，不再用重复的右侧白色“决策摘要”卡片堆叠；
- 正文按 `01—05` 大编号组织，暖白与深色章节交替；
- 实施步骤、指标、风险和匹配服务使用不同的排版语法，而不是全部渲染成相同列表；
- 移动端转为单栏自然流，事实带可换行但不得横向滚动。

示意稿中的 `12 周`、`35—60%`、`40—80%` 等数字只用于证明排版容纳能力，不得复制为业务事实。页面只能显示仓储投影提供的已发布数据；演示数字必须逐项紧邻标注“演示数据”。

## 3. 视觉语言

### 3.1 色彩

全站只使用一套主色系统：

| 变量 | 值 | 用途 |
|---|---:|---|
| `graphite-1000` | `#06080B` | 导航、沉浸封面、深色章节 |
| `graphite-950` | `#0B1016` | 次深背景、图片遮罩 |
| `graphite-850` | `#18202A` | 深色分隔线、次级面 |
| `paper-050` | `#F3F1EB` | 编辑式正文背景 |
| `paper-000` | `#FBFAF7` | 表单和重点信息面 |
| `ink-950` | `#111827` | 亮色页面主标题和正文 |
| `ink-650` | `#556070` | 次级说明 |
| `silver-200` | `#D8DEE6` | 深色页面正文、高光线 |
| `signal-blue` | `#0F6FEF` | 唯一品牌强调色、链接、主按钮 |

不得继续使用青色、橙色、紫色或彩虹渐变作为第二强调体系。风险信息通过标题、边框、排序和文字说明表达，不新增高饱和警示色破坏整体系统。

### 3.2 图像亮度与处理

- `home-ai-core.webp` 和后续工业图像必须保留银灰主体和可辨识高光；禁止对整张图片使用 `invert()`、`hue-rotate()` 或把主体亮度压到不可辨识的组合滤镜。
- 图片暗化只能由容器内局部遮罩完成，且遮罩不得覆盖主要人物、机械结构或信息焦点。
- 图片负责氛围，不承担标题、指标、按钮或事实文本。
- 所有生产图片使用本地静态资源或已发布媒体端点；不得运行时请求外部图片。
- 图像采用轻微悬停放大，范围为 `1.01—1.025`，不得使用漂浮、旋转、粒子或连续循环动画。

### 3.3 字体与排版

不加载外部字体，使用本机可用的中文无衬线栈：`"Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif`。数字和短英文标签可使用 `Inter, Arial, sans-serif` 回退，但不能产生网络字体请求。

- 首页主标题：桌面 `72—96px`，行高 `0.98—1.04`，字重 `650—750`，字距 `-0.035em`；手机 `42—56px`。
- 目录页主标题：桌面 `56—72px`；详情页主标题：桌面 `64—88px`；移动端不小于 `40px`。
- 章节标题：`36—52px`；正文：`17—19px`、行高 `1.65—1.8`；辅助文字不小于 `14px`。
- 中文标题不使用整句渐变、不使用描边字、不用全大写伪装科技感。设计感来自字阶、窄行宽、留白、编号和对齐。
- 正文阅读宽度控制在 `62—72ch`；不能出现当前详情页将大量部门或标签连续挤成一段的情况。

### 3.4 几何与留白

- 最大内容宽度 `1280px`；桌面 gutter `32px`，平板 `24px`，手机 `20px`。
- 大区块上下留白 `120—180px`；目录结果行 `48—72px`；详情章节 `96—144px`。
- 常规圆角 `0—4px`，表单控件可为 `4—6px`；阴影极弱或不用。
- 章节边界使用 `1px` 细线；禁止大面积浮空白卡、厚阴影和多层圆角容器。

## 4. 公共页面架构

### 4.1 全局公共外壳

适用：除管理员后台外的全部公开页面。

- 导航统一为近黑背景、白色品牌字和银灰导航文字；当前栏目使用细蓝线或蓝色文字，不使用大胶囊标签。
- 首页与内页共享同一高度、Logo 尺寸、导航间距和移动菜单行为。
- 顶部标语合并进导航或取消独立黑条，避免现在的“双层头部”。
- 页脚使用深色大区块和清晰列结构；移动端为单列或两列，不出现压缩的四列小字。
- 固定行动条只在真正需要持续转化的页面出现；首页最终 CTA 与固定行动条不得重复竞争。

### 4.2 目录与列表模板

适用：行业、场景、服务包、案例、资源和公告列表。

统一结构：

1. 暗色编辑式页头：栏目编号/英文短标签、56—72px 标题、短说明和一张局部工业视觉；无合适媒体时使用纯暗色排版，不生成占位框。
2. 筛选控制带：作为一条紧凑的横向工作区嵌入内容，不再是独立大白卡；移动端按字段垂直排列。
3. 结果区：优先使用大行、错位图文或跨栏条目。三列小卡仅用于内容数量足够、信息结构确实同构的次级内容。
4. 单条或少量内容：使用全宽编辑式条目和更大的信息说明，不能把一个案例缩成左上角孤立小卡片。
5. 分页和空状态：维持真实 URL、筛选参数和键盘可操作性；空状态不得伪造内容。

场景目录继续保留行业、部门、成熟度和每页数量筛选；结果行必须明显区分标题、适用范围、成熟度和入口。行业、服务、案例和资源列表不得因为套用同一宏而看起来完全相同。

### 4.3 决策详情模板

适用：行业、场景和服务包详情。

统一结构：

1. 分栏封面：左侧栏目、标题、摘要；右侧使用符合内容的已发布媒体或本地工业图像。
2. 横向事实带：行业、部门、成熟度、周期、预算或企业规模按页面实际字段选择；没有数据时显示规格允许的诚实退化值，不重复字段。
3. 编号正文：内容块和结构化字段被编排为语义章节，不改变字段来源。
4. 深色路径章节：场景实施步骤、服务交付阶段或行业落地路径使用横向/纵向流程排版。
5. 证据与风险章节：指标使用大数字或强对齐行；风险使用表格式治理信息；都必须显示真实投影。
6. 最终匹配行动：相关服务、案例、资源和评估入口集中在末尾，不在右侧反复复制同一 CTA。

场景页按照问题边界、实施路径、可衡量指标、风险治理、匹配服务五章编排。行业页按照行业判断、业务痛点、优先场景、落地路径、相关证据编排。服务页按照服务定位、适用条件、交付范围、周期预算、下一步编排。

### 4.4 编辑内容与信任页面模板

适用：案例详情、资源详情、公告详情、关于、错误页。

- 案例详情使用“证据文章”结构：核验状态和时间为窄元数据带，量化指标使用大数字行，证据说明保持可阅读行宽。
- 资源详情使用“审核档案”结构：来源、版权、附件和审核时间形成清晰元数据表，正文内容块保持编辑式节奏。
- 公告详情使用“动态文章”结构：时间、有效期和正文分层，不套决策详情布局。
- 关于页使用平台定位、原则、能力边界和行动区四个大章节；减少连续粗体长段落。
- 错误页保持同一公共外壳，用短说明和单一恢复操作，不添加装饰性假数据。

### 4.5 评估与转化页面

- 评估页保留现有六步行为、字段、校验、会话、CSRF 和分析事件；只重构视觉层级。
- 页面以暗色引导区进入暖白表单工作区；步骤、问题标题、选择项和主要行动形成明确顺序。
- 选择项保持完整可点击区域和至少 `44×44px` 目标；错误、选中、焦点和禁用状态必须可区分。
- 报告和 PDF 不在本轮公共页面重构中改变内容结构；只允许继承不会破坏打印的公共令牌。

## 5. 内容块的视觉映射

七类已验证内容块继续使用现有安全投影，但必须具有不同视觉语法：

| 区块 | 视觉表达 |
|---|---|
| `heading` | 编辑式章节标题，保持正确标题层级 |
| `rich_text` | 62—72ch 阅读列，列表和段落有明确节奏 |
| `image_text` | 宽图与正文左右错位；移动端图在文前 |
| `metric` | 大数字、单位和说明三层，不伪造数字 |
| `steps` | 编号路径或阶段轨道，不用普通圆角卡 |
| `download` | 审核附件行，显示文件动作与说明 |
| `cta` | 章节尾单一行动区；外链继续使用安全属性 |

富文本继续经过既有 allowlist 清洗，CTA URL 继续经过既有安全校验，媒体只走已发布媒体端点。视觉模板不得绕开这些边界。

## 6. 动效与交互

- 只使用进入视口后的淡入和 `12—24px` 轻微位移，时长 `500—800ms`。
- 图片悬停只做轻微放大；导航滚动时可由透明变为实色或收紧高度。
- 不使用视频、轮播图、自动横向跑马灯、炫技粒子、3D 实时渲染或滚轮劫持。
- `prefers-reduced-motion: reduce` 下取消过渡、粘性叙事和自动位移，内容保持完整可见。
- 无 JavaScript 时，筛选表单、导航、详情、内容块和 CTA 仍可在普通文档流中使用。

## 7. 响应式与可访问性

- 验收视口：`1440×1024`、`1024×900`、`910×900`、`390×844`，并检查 `320px` 边界。
- 1440px：分栏首屏、1280px 对齐和大字号成立；没有空洞卡片矩阵。
- 1024/910px：图文比例收缩或改为上下排列；导航和事实带不覆盖正文。
- 390/320px：单栏自然流、无页面级横向溢出、图片焦点可辨、按钮和控件至少 `44×44px`。
- 每页一个 `h1`，标题层级连续；保留 skip link、可见焦点、语义 landmark 和表单 label。
- 正文、导航、边框、焦点和按钮至少达到 WCAG 2.2 AA 对比要求；截图只能证明视觉风险，原生键盘和缩放必须单独记录真值。

## 8. 数据、安全与真实性边界

- 全部页面只消费现有已发布 view model，不新增直接 SQL、数据库字段或生产 API。
- 不显示未发布、已归档、未审核或来源失效的内容与媒体。
- 不出现未经授权的客户名称、Logo、引语、ROI、节省比例或规模数据。
- 演示指标必须逐项标注“演示数据”；无数据时显示诚实空状态，不用占位数字填满版面。
- 保留 canonical、SEO 描述、来源、版权、附件、安全外链和缓存边界。
- 本轮不解决阶段 5A Task 12 的原生键盘证据，也不把该任务或阶段 5B 标记为完成。

## 10. 验收门槛

1. 首页机械手与绑定基准同视口比较，主体为明亮银灰，不再受整图反色或过度降亮度影响。
2. 行业、场景、服务、案例、资源、评估和关于等 12 个代表页面均有 fresh 桌面截图；场景目录、场景详情和评估另有手机截图。
3. 详情页与绑定详情基准进行同视口比较，首屏分栏、事实带、编号章节、深浅节奏、图像亮度和字阶无 P0—P2 差异。
4. 列表页不再以三列同质白卡作为主要表达；单条内容不会孤立在页面左上角。
5. 导航、筛选、分页、详情入口、评估 CTA、附件和安全外链均使用真实路由并可操作。
6. 1440/1024/910/390/320 无横向溢出、遮挡、重叠、不可达控件或图片焦点错误。
7. Python 聚焦责任集、Node 运行时、语法检查、`git diff --check` 和本地 Browser 主流程具有新鲜证据。
8. `design-qa.md` 最终为 `final result: passed`，每个独立任务和完整计划审查无未闭合 P0—P2。
9. 原生 Tab/Shift+Tab/Enter/Space、reduced-motion 和 200% zoom 逐项记录 PASS/FAIL/NOT PROVEN，不以 HTTP、Node 或程序化 focus 冒充。
10. 不运行未经计划授权的最终 full suite，不部署、不联网、不接触生产。

## 11. 实施顺序

实施拆为五个可独立审查的阶段：

1. 银灰图像、设计令牌和统一公共外壳；同时修正首页机械手亮度与字体基线。
2. 行业、场景、服务、案例、资源和公告目录模板。
3. 行业、场景和服务决策详情模板及七类内容块。
4. 案例、资源、公告、关于、错误和评估页面。
5. 四视口 Browser QA、交互真值、完整独立审查与用户视觉验收。

每个阶段必须真实 RED→GREEN、单独提交并独立复审。第五阶段完成只代表公共 UI 在本地达到验收门槛，不代表全部功能、最终 full suite 或生产部署完成。
