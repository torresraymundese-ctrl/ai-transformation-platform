# 企业 AI 转型平台 2.0 全站 UI 设计规格

- 日期：2026-08-26
- 状态：视觉方向已确认，等待本书面规格确认
- 适用范围：阶段 6 设计系统与页面升级，以及阶段 5 后续页面的统一 UI 接入
- 视觉基准：`docs/design/evidence/2026-08-26-ui-visual-baseline.png`
- 生产边界：仅限本地设计、开发和演示；全部功能开发、独立审查与完整测试通过前不得部署或改动生产环境

## 1. 设计目标

平台采用“可信的企业决策内容 + 清晰的业务行动入口”作为统一体验。设计必须解决当前公开详情页内容裸排、页面层级不足、后台表单密集且操作反馈弱的问题，同时保持现有 Flask 路由、服务边界、发布状态、安全校验和数据契约不变。

目标用户主要是需要快速判断 AI 场景是否适用、实施条件和下一步行动的企业业务负责人，以及维护内容和线索的两位后台运营人员。公开页面优先帮助用户理解和决策；后台页面优先帮助运营人员减少误操作并确认保存、发布、排期和归档结果。

本次设计不以增加装饰为目标，也不把每段内容包装成卡片。优先使用排版、留白、对齐、分组和分隔线建立层级。

## 2. 已确认的视觉方向

最终方向由三部分组成：

1. 公共端采用编辑式双栏结构：左侧为可阅读的业务内容，右侧为决策摘要和行动入口。
2. 详情页吸收咨询报告的专业感：深蓝主题区、编号章节、明确结论层级，但避免高密度表格和报告式压迫感。
3. 后台吸收工作台式信息架构：清晰的导航、状态区、分段表单和固定操作区；公开页面不使用持久侧边栏、头像、通知或后台式应用框架。

获选基准稿只定义视觉语言和布局意图。稿中的示例正文不是业务事实，实际页面只能渲染正式 view model 中已验证、已发布的数据。

## 3. 设计原则

### 3.1 真实数据优先

- 行业、部门、步骤、风险、预算、周期、指标、交付物和关联内容只能来自已验证的结构化数据或已发布内容块。
- 不展示虚构的客户、头像、通知、完成度、ROI、覆盖数量、评估状态或案例结果。
- 可选预算或周期缺失时显示“评估后确认”；发布规格要求必填的数据缺失时继续由发布门禁阻止公开，不用占位文案掩盖错误。
- 模板不直接查询数据库，不绕过 repository/view model，也不在前端重新解释业务状态。

### 3.2 层级优先于装饰

- 同一页面最多一个主要行动，允许一个弱化的返回或了解更多操作。
- 正文主要依靠标题、段落、编号、列表和分隔线；只有可独立操作或比较的对象使用卡片。
- 阴影仅用于浮层、移动菜单和必要的粘性操作区；常规内容不用悬浮卡片效果。
- 图标是辅助信息，不替代文字。若仓库没有可复用的本地图标库，则保留清晰文字标签，不用 emoji、字符图标、CSS 图形或临时手绘 SVG 代替。

### 3.3 一致但不单调

- 公共营销页、决策详情页、评估与报告、后台工作台共享相同的颜色、字体、间距、圆角、按钮、表单和反馈语义。
- 各页面家族使用适合任务的布局，不强行套用同一种卡片网格。
- 公开端强调可信和可读，后台强调效率、状态和错误预防。

## 4. 视觉基础

### 4.1 色彩

现有蓝色品牌资产继续作为主色，不更换 Logo，不创建新的品牌标志。

| 语义 | 建议值 | 用途 |
|---|---|---|
| 深蓝 `navy-950` | `#061B46` | 详情页主题区、重要深色表面 |
| 主蓝 `blue-600` | `#0F5FEF` | 主按钮、活动导航、链接和焦点 |
| 主蓝深色 `blue-700` | `#0B49BF` | hover/pressed 状态 |
| 青色 `teal-700` | `#007C91` | 输入、资料和次级正向信息 |
| 琥珀 `amber-700` | `#9A5B00` | 已审核风险和警示信息 |
| 正文 `ink-950` | `#15213A` | 主文本 |
| 次级文本 `ink-650` | `#536176` | 描述和元数据 |
| 分隔线 `line-200` | `#DDE4EE` | 边框和分隔线 |
| 浅背景 `surface-050` | `#F6F8FB` | 次级页面区和后台背景 |
| 白色 `surface-000` | `#FFFFFF` | 主页面表面 |

正文、按钮、链接、风险和状态组合必须达到 WCAG 2.2 AA 对比度。状态不能只用颜色表达，必须同时有文字或图形含义。

### 4.2 字体

- 使用系统中文无衬线字体栈：`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、系统 sans-serif。
- 不从外网加载字体，不增加首屏网络依赖。
- 正文桌面端 16px、行高 1.75；移动端不低于 16px。
- 页面标题建议 48px/1.15，详情标题 44px/1.2，一级区块标题 28px/1.3，二级标题 20px/1.4。
- 长正文最大阅读宽度约 65 个中文字符，不用超轻字重。

### 4.3 间距、圆角与尺寸

- 使用 8px 基础间距网格，常用间距为 8、12、16、24、32、48、64、80。
- 页面最大宽度 1200px；桌面横向 gutter 24px，平板 20px，移动端 16px。
- 控件最小点击区域 44×44px。
- 常规控件圆角 8px，面板 12px，强调按钮可使用 10px；不再默认使用超大胶囊和 20px 以上圆角。
- 常规卡片不使用位移动画；交互状态以颜色、边框和轻微阴影变化为主。

### 4.4 动效

- 页面进入和区块出现只允许轻微透明度/位移，持续时间 160—240ms。
- 表单错误、发布反馈和保存状态应即时出现，不使用延迟动画。
- `prefers-reduced-motion: reduce` 时关闭非必要动画和滚动效果。
- 不使用持续浮动、视差、发光或抢夺注意力的循环动效。

## 5. 全局组件

### 5.1 导航

- 桌面导航维持已冻结的信息架构：行业方案、AI 场景、服务与交付、案例与资源、关于我们、免费评估。
- 使用官方 `static/logo.png`，Logo 与文字保持清楚的可点击首页入口。
- 当前栏目有可见活动状态，不只依赖颜色；键盘焦点必须清楚。
- “免费评估”是全局主按钮并指向现有 `/assessment`。
- 移动端使用可关闭的折叠菜单，菜单打开后焦点顺序、Escape/关闭行为和页面滚动均可控。

### 5.2 按钮与链接

- 主按钮：实心主蓝，用于当前页面唯一的核心动作。
- 次按钮：白底主蓝边框，用于返回列表、查看详情或取消。
- 危险动作：文本明确并要求确认，不把归档、删除做成普通主按钮。
- 同一页面不得出现多个视觉权重相同但目的不同的主按钮。
- 场景详情的“获取适配建议”可以进入现有评估流程，并通过已有埋点属性记录页面来源；不为视觉需要发明新 API。

### 5.3 表单与反馈

- 标签始终可见，不用 placeholder 代替标签。
- 必填、帮助文本、字段错误和全局错误摘要使用统一结构。
- 保存、发布、排期、归档和冲突分别有明确结果状态；失败后保留用户输入和当前编辑上下文。
- 锁冲突或旧版本冲突必须说明“内容已被其他操作更新”，并提供安全的重新载入路径。
- 后台长表单使用分段标题和说明，不在一个连续白页中裸排全部字段。

### 5.4 内容块

七类受控内容块使用统一、安全的公开渲染组件：

| 类型 | 公开呈现 |
|---|---|
| `rich_text` | 清洗后的正文，使用正文排版和受控链接样式 |
| `heading` | 按验证后的 level 输出语义标题，不改变文档标题层级 |
| `image_text` | 已发布媒体端点图片、alt 和配套正文，桌面可双栏、移动端单栏 |
| `metric` | 数值、单位和说明组成一组；不补造缺失数值 |
| `steps` | 有序编号步骤和短说明，避免每步独立大卡片 |
| `download` | 明确文件类型/说明和安全下载操作 |
| `cta` | 经过安全 URL 校验的主要或次要行动，不允许任意协议 |

空内容块不产生空白面板。结构错误或 legacy 非法公开内容继续 fail closed，不由 CSS 隐藏错误。

## 6. 页面家族

### 6.1 首页与列表页

- 首页保留主价值、行业入口、热门场景、方法、案例/资源和评估入口，但每屏只承担一个核心叙事任务。
- 列表页顶部使用紧凑标题和简介，筛选区与结果区分离。
- 桌面筛选可以横向排列；移动端折叠为“筛选”控制，展开后仍保留原有 query 和已选状态。
- 内容卡片统一展示类型、标题、摘要和少量已验证元数据，不因字段缺失产生空标签。
- 无结果状态说明原因并提供清除筛选或返回完整目录的动作。

### 6.2 行业、场景与服务包详情

- 使用获选基准稿的“主题区 + 8/4 双栏”结构。
- 主题区只展示 breadcrumb、标题、摘要和少量已验证分类信息。
- 左侧呈现主要内容、步骤、输入、输出、指标和风险；右侧为决策摘要、周期、预算、关联对象和行动入口。
- 右侧摘要在桌面可粘性定位，但不得遮挡页脚或系统提示；移动端移到主题区之后并取消粘性。
- 行业详情的场景集合、场景详情的服务/案例/资源关系、服务包的交付物均使用 published-only view model。
- 上下文 CTA 使用“获取适配建议”，次操作使用“返回场景列表”或对应列表文案。

### 6.3 案例、资源、公告与关于页面

- 案例优先展示经审核的背景、方法和指标；匿名状态与指标说明必须可见。
- 资源和公告使用舒适正文宽度、清楚的标题层级、来源/日期/下载信息和安全外链样式。
- 关于和法律页面使用简洁正文布局，不套用决策摘要栏。
- SEO 标题、描述和 canonical 继续来自可信服务端配置，不从 Host 头构造。

### 6.4 评估与报告

- 评估继续采用单任务、多步骤体验，每屏只展示当前问题组。
- 顶部显示可理解的步骤标题和进度，不用虚假完成率或行业平均值。
- 选择项有完整 hover、focus、selected、disabled 和 error 状态；返回修改不丢失当前标签页内非个人答案。
- 报告使用同一设计系统，但保留数据图表、匹配说明、ROI 免责声明、行动计划和 PDF 打印边界。
- “平台建议就绪参考线”不得改写为“行业平均”。

### 6.5 后台工作台、列表和编辑器

- 桌面后台采用固定宽度的主导航区、页面标题/状态区和内容工作区；不显示无真实功能的头像、通知或团队控件。
- 工作台只呈现可行动的待办、近期变化和快捷入口，不堆砌装饰性指标。
- 列表页统一搜索、筛选、分页、状态标签和空状态；批量操作仅在已有业务能力支持时展示。
- 编辑器按“基本信息、公开内容、关系与媒体、SEO、发布设置”分段。
- 保存草稿、预览、排期、发布和归档使用固定操作区，按钮权限和字段契约继续由服务端决定。
- 发布前校验错误跳转并聚焦到对应分段；成功反馈包含对象、动作和当前状态。
- 原始 ID、lock version、修订号等技术字段只在确有运营价值的位置展示，避免占据主要编辑区域。

## 7. 响应式规则

### 7.1 断点

- 大桌面：`>= 1200px`
- 桌面/小型笔记本：`1024—1199px`
- 平板：`768—1023px`
- 移动端：`< 768px`
- 小屏移动端：`< 390px`

### 7.2 重排

- 12 栏页面在平板缩为 8 栏，移动端为单栏。
- 详情页右侧决策摘要在移动端移到正文前，不保留悬浮或 fixed 定位。
- 五步以上横向步骤在窄屏转为纵向有序列表，不允许横向溢出。
- 桌面表格在移动端优先减少非关键列；确需横向滚动时提供清楚容器边界，不把每行随意拆成卡片。
- 后台固定操作区在移动端变为底部操作条，并避免遮挡字段错误和系统浏览器控件。
- 320px 宽度不得出现页面级横向滚动；图片、富文本和长 URL 必须安全换行。

## 8. 可访问性

- 页面提供“跳到主要内容”链接，使用语义化 `header/nav/main/footer`。
- 每页只有一个 `h1`，内容块标题不跳级。
- 全站可通过键盘到达并操作导航、筛选、表单、对话框和后台动作。
- `:focus-visible` 使用至少 3px 的高对比焦点环，不被 sticky 元素或 overflow 裁切。
- 错误摘要使用 `role=alert` 或等价语义，并通过字段 `aria-describedby` 关联错误。
- 媒体必须有与内容用途一致的 alt；纯装饰资产使用空 alt。
- 触控目标至少 44px，文本缩放至 200% 后仍不丢失内容或操作。
- 减少动效偏好、颜色对比和非颜色状态表达属于发布前阻断验收项。

## 9. 性能与资产边界

- 不加载第三方字体、远程图标、远程分析脚本或真实外网设计资源。
- 优先复用现有 Logo、二维码、已发布媒体和本地静态资产。
- 图片必须提供明确尺寸，避免布局偏移；列表图使用合适缩略尺寸，不下载原图后仅靠 CSS 缩放。
- 首屏不依赖大型装饰图片。深蓝主题区可使用纯色或轻量渐变；若未来加入几何品牌图形，必须是经过批准并落盘的真实资产。
- JavaScript 只承担菜单、筛选、表单和必要交互，不用脚本重建服务端已经生成的正文。
- CSS 按 foundations、components、public pages、assessment/report、admin 分层，防止继续在单个全局文件中堆叠无边界规则。

## 10. 实现架构边界

设计升级只改变表现层和必要的 view model 适配，不改变以下契约：

- 保留现有 Flask 模块化单体、URL、repository/service 事务边界和权限边界。
- 保留内容修订、锁、排期、发布、归档、媒体和关系的精确字段验证。
- 保留公开内容 published-only、canonical、noindex、安全 URL、HTML 清洗和媒体下载规则。
- 保留评估、报告、线索、预约和埋点的数据语义。
- 模板只消费明确 view model；因呈现需要新增字段时，必须从 repository/service 提供经过验证的只读投影，并用 TDD 锁定。
- UI 不能把服务端拒绝的组合呈现为可提交状态；动态选择器必须保持类型、目标和状态一致。

## 11. 实施分段

设计实现按以下顺序进行，每段独立 TDD、浏览器 QA、代码审查和提交：

1. Foundations：设计令牌、基础排版、按钮、表单、提示、导航、页脚和响应式容器。
2. Public catalog：首页、行业/场景/服务/案例/资源列表与详情，以及七类内容块。
3. Assessment and report：评估流程、简版结果、完整报告和打印/PDF 对齐。
4. Admin operations：登录、工作台、列表、编辑器、媒体、线索、预约和规则运营页面。
5. Cross-page QA：响应式、键盘、视觉一致性、SEO、性能和主旅程回归。

后续阶段 5 新增页面必须直接使用本设计系统，避免先生成裸页面再进行第二次重做。未完成的业务能力仍按既定功能计划和审查门禁推进，视觉实现不能被误记为功能完成。

## 12. 测试与验收

### 12.1 自动化

- 保留所有现有业务、安全、内容发布和评估回归。
- 为共享组件增加模板/HTTP 断言：语义结构、活动导航、CTA、published-only 数据、空状态和错误状态。
- 为移动菜单、筛选、表单状态和后台操作增加真实事件级 JavaScript 测试。
- 对七类内容块分别覆盖发布到公开 HTTP 的完整呈现，不只检查 section 标记。
- CSS/模板变更不得降低 canonical、robots、URL 安全、富文本清洗或 CSRF 门禁。

### 12.2 浏览器

- 代表性视口至少覆盖 1440×1024、1024×768、768×1024 和 390×844。
- 对首页、列表、三类详情、评估、报告、后台工作台和编辑器保存对照截图。
- 使用相同 viewport 将获选基准或批准页面稿与实现截图并排比较，检查结构、间距、字号、颜色、断点、裁切和状态。
- 使用具有真实默认键盘行为的本地浏览器验证 Tab、Shift+Tab、Enter、Space、Escape 和 select；HTTP、Node 或程序化 focus 不替代该证据。
- 验证 200% 文本缩放、减少动效、长中文、长 URL、空数据、错误、加载和冲突状态。

### 12.3 完成门槛

某一页面家族只有同时满足以下条件才可标记完成：

1. 使用真实或确定性测试数据，不展示设计稿中的模拟事实。
2. 桌面和移动端无页面级横向溢出、遮挡或关键内容丢失。
3. 主动作、筛选、表单、菜单和后台状态可以真实操作。
4. 自动化责任集、JavaScript 测试和浏览器视觉/键盘验收均有新鲜证据。
5. 独立审查无未闭合 P0—P2。
6. 未触碰生产服务器、Nginx、systemd、真实数据库或真实外网。

## 13. 非目标

- 不更换 Logo 或创建新品牌。
- 不引入前端 SPA、CSS 框架或全新模板引擎。
- 不因视觉升级改变评估规则、内容发布规则、数据库 schema 或业务状态机。
- 不新增用户中心、多账号、通知中心或在线支付。
- 不用设计稿中的示例信息填充生产内容。
- 不在完整功能、独立审查和全量验收前部署、开放公网或修改生产基础设施。

## 14. 决策摘要

- 公共端：方案 1 的编辑式可读性为主，加入方案 3 的深蓝主题和编号节奏。
- 后台端：只吸收方案 2 的信息组织方式，不复制其虚构用户和应用控件。
- 全站：真实数据、克制视觉、响应式和可访问性优先于装饰。
- 技术：渐进增强现有 Flask/Jinja/CSS/JS，不改业务和安全边界。
- 发布：本地完成所有功能、审查和完整测试后，才允许进入生产部署阶段。
